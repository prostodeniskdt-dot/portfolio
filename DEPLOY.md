# Развёртывание портфолио на Timeweb Cloud

Пошаговая инструкция по деплою **статического сайта** в [Timeweb Cloud](https://timeweb.cloud/) через **App Platform** (тип Next.js).

---

## Что подготовлено в репозитории

- В **next.config.mjs** включён статический экспорт: **`output: 'export'`**. Папка **`distDir`** не задаётся — экспорт идёт в стандартную папку **`out`**, иначе на платформе падает шаг «Unpacking static».
- После `npm run build` Next.js создаёт статику в **`out`**, затем скрипт **`scripts/copy-out.js`** копирует её в **`dist/barboss/browser`** (на случай, если в панели указана эта директория).
- В **package.json** добавлен **postbuild**: `node scripts/copy-out.js`.

В настройках приложения укажите параметры сборки, как в таблице ниже. **Директорию сборки лучше указать `out`** — так платформа корректно находит статику.

---

## Шаг 1. Регистрация и вход

1. Перейдите на [timeweb.cloud](https://timeweb.cloud/).
2. Нажмите **«Войти»** или **«Создать аккаунт»**.
3. Откройте **«Сервисы»** → **«App Platform»**.

---

## Шаг 2. Тип приложения

1. Нажмите **«Создать приложение»**.
2. В блоке **«Тип»** выберите **«Next.js»** (Runtime: **Node.js 24**).
3. Подключите репозиторий (GitHub / GitLab / Bitbucket или URL). Если репозиторий приватный — укажите логин и токен доступа.

---

## Шаг 3. Ветка и коммит

1. Выберите **ветку** для деплоя (например, `main`).
2. При желании включите **«Сборка по последнему выполненному коммиту»** — при пуше в эту ветку будет запускаться автодеплой.

---

## Шаг 4. Регион и конфигурация сервера

1. Выберите **регион** (Россия/СПб, Польша, Нидерланды и т.д.).
2. Выберите **тариф** — для статического сайта достаточно минимального.

---

## Шаг 5. Настройка приложения (важно)

В разделе **«5. Настройка приложения»** укажите:

| Поле | Значение |
|------|----------|
| **Команда сборки** | `npm run build` |
| **Зависимости** | оставить пустым |
| **Директория сборки** | **`out`** (рекомендуется; при использовании `dist/barboss/browser` статика туда копируется в postbuild) |

В блоке **«Переменные»** для статического сайта ничего добавлять не нужно (при необходимости можно добавить позже).

---

## Шаг 6. Дальнейшие шаги

1. **Приватная сеть** — по желанию, для простого статического сайта можно пропустить.
2. **Имя приложения** и **проект** — задайте по своему усмотрению.
3. Нажмите **«Запустить деплой»**.

---

## После деплоя

- На вкладке **«Дашборд»** будут **IP** и **технический домен** (например, `xxx.twc1.net`). Сайт доступен по HTTP/HTTPS.
- Свой домен можно привязать в настройках приложения: [инструкция Timeweb](https://timeweb.cloud/docs/apps/upravlenie-apps-v-paneli#privyazka-domena).

---

## Проверка сборки локально

Перед пушем можно убедиться, что статика попадает в нужную папку:

```bash
npm install
npm run build
```

После успешной сборки должна появиться папка **`dist/barboss/browser`** с файлами сайта (в т.ч. `index.html`).

## Если деплой падает на шаге «Unpacking static»

- Убедитесь, что в **next.config.mjs** задано **`output: 'export'`** и **не задано** `distDir` (экспорт должен идти в папку **`out`**).
- В настройках приложения в поле **«Директория сборки»** укажите **`out`**.

После изменений пересоберите и заново запустите деплой.

Подробности — в [документации Timeweb по Dockerfile](https://timeweb.cloud/docs/apps/deploying-with-dockerfile).
