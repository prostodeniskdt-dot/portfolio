# Развёртывание портфолио на Timeweb Cloud

Пошаговая инструкция по деплою **статического сайта** в [Timeweb Cloud](https://timeweb.cloud/) через **App Platform**.

---

## Рекомендуемый способ: тип **«Dockerfile»**

Чтобы контейнер после сборки **запускался и проходил health check**, в Timeweb нужно выбрать тип **«Dockerfile»**, а не «Next.js». В репозитории лежит **Dockerfile** с явными **EXPOSE 8080** и **CMD** (`npx serve out -l 8080`). Без них платформа не знает, на каком порту слушает приложение, и контейнер после старта ничего не запускает — деплой помечается как «Ошибка при сборке» (фактически падает health check).

- **Next.js** (тип приложения): платформа подставляет свой шаблон Dockerfile **без CMD** — контейнер сразу завершается, health check не проходит.
- **Dockerfile**: используется наш Dockerfile с **EXPOSE 8080** и **CMD** — контейнер запускает `serve` на порту 8080, деплой проходит.

Ниже описаны оба варианта; для стабильного деплоя предпочтите **«Dockerfile»**.

---

## Что подготовлено в репозитории

- **next.config.mjs**: **`output: 'export'`**, без `distDir` — экспорт идёт в папку **`out`**.
- **Dockerfile**: одностадийная сборка (node:24-slim), установка зависимостей, `npm run build`, **EXPOSE 8080**, **CMD ["npx", "serve", "out", "-l", "8080"]**.
- **Dockerfile.nginx**: альтернатива с Nginx (меньший образ), см. в конце.
- **package.json**: **start** = `serve out -l 8080`; **postbuild** копирует статику в `dist/barboss/browser` (для варианта «Next.js» с указанной директорией сборки).

**API routes** (`/api/contact`, `/api/error`): при **статическом экспорте** они не работают (в билде помечены как Dynamic, но в проде серверных маршрутов нет). Для бэкенда нужен отдельный сервис или отказ от `output: 'export'`.

---

## Шаг 1. Регистрация и вход

1. Перейдите на [timeweb.cloud](https://timeweb.cloud/).
2. Нажмите **«Войти»** или **«Создать аккаунт»**.
3. Откройте **«Сервисы»** → **«App Platform»**.

---

## Шаг 2. Тип приложения и репозиторий

1. Нажмите **«Создать приложение»**.
2. В блоке **«Тип»** выберите вкладку **«Dockerfile»** (в корне репозитория должен быть файл **Dockerfile**).
3. Подключите репозиторий (GitHub / GitLab / Bitbucket или URL). Если репозиторий приватный — укажите логин и токен доступа.

Если выбран тип **«Next.js»**, платформа использует свой шаблон без CMD — контейнер не запустит сервер, возможна ошибка после «Build succeeded» или «Ошибка при сборке» из-за неудачного health check. В этом случае пересоздайте приложение с типом **«Dockerfile»**.

---

## Шаг 3. Ветка и коммит

1. Выберите **ветку** для деплоя (например, `main`).
2. При желании включите **«Сборка по последнему выполненному коммиту»** — при пуше в эту ветку будет запускаться автодеплой.

---

## Шаг 4. Регион и конфигурация сервера

1. Выберите **регион** (Россия/СПб, Польша, Нидерланды и т.д.).
2. Выберите **тариф** — для статического сайта достаточно минимального.

---

## Шаг 5. Настройка приложения

При типе **«Dockerfile»** сборка и запуск задаются в самом Dockerfile (EXPOSE 8080, CMD). Дополнительные переменные окружения при необходимости укажите в панели.

Если вы используете тип **«Next.js»**, в разделе «5. Настройка приложения» укажите:

| Поле | Значение |
|------|----------|
| **Команда сборки** | `npm run build` |
| **Зависимости** | оставить пустым |
| **Директория сборки** | **`out`** |

Переменные для статического сайта не обязательны.

---

## Шаг 6. Дальнейшие шаги

1. **Приватная сеть** — по желанию, для простого статического сайта можно пропустить.
2. **Имя приложения** и **проект** — задайте по своему усмотрению.
3. Нажмите **«Запустить деплой»**.

---

## После деплоя

- На вкладке **«Дашборд»** будут **IP** и **технический домен** (например, `xxx.twc1.net`). Сайт доступен по HTTP/HTTPS.
- Свой домен можно привязать в настройках приложения: [инструкция Timeweb](https://timeweb.cloud/docs/apps/upravlenie-apps-v-paneli#privyazka-domena).

---

## Проверка сборки локально

Перед пушем можно убедиться, что статика попадает в нужную папку:

```bash
npm install
npm run build
```

После успешной сборки должна появиться папка **`dist/barboss/browser`** с файлами сайта (в т.ч. `index.html`).

## «Ошибка при сборке» или падение после «Build succeeded»

Часто это **не ошибка сборки**, а неудачный **health check**: контейнер собрался, но не слушает порт (нет процесса). Решение:

1. Выберите тип приложения **«Dockerfile»** (не «Next.js»). В нашем Dockerfile заданы **EXPOSE 8080** и **CMD ["npx", "serve", "out", "-l", "8080"]** — контейнер запускает сервер и отвечает на порту 8080.
2. При статическом экспорте **не используется** `next start` — в проекте запуск идёт через **serve** (в Dockerfile по CMD, в package.json по скрипту **start**).

---

## Если деплой падает на шаге «Unpacking static»

- Убедитесь, что в **next.config.mjs** задано **`output: 'export'`** и **не задано** `distDir` (экспорт должен идти в папку **`out`**).
- В настройках приложения в поле **«Директория сборки»** укажите **`out`**.

После изменений пересоберите и заново запустите деплой.

---

## Альтернатива: образ с Nginx (Dockerfile.nginx)

Для меньшего размера образа можно собрать его по **Dockerfile.nginx** (многостадийная сборка: Node → Nginx, раздача статики на порту 8080). В панели Timeweb при создании приложения укажите путь к Dockerfile: **Dockerfile.nginx** (если платформа это поддерживает), либо переименуйте файлы локально и запушьте. Документация: [деплой из Dockerfile в Timeweb](https://timeweb.cloud/docs/apps/deploying-with-dockerfile).
