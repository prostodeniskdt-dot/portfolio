# Развёртывание портфолио на Timeweb Cloud

Пошаговая инструкция по деплою **статического сайта-визитки** [portfolio](https://github.com/prostodeniskdt-dot/portfolio) в [Timeweb Cloud](https://timeweb.cloud/) через **App Platform** и привязке своего домена.

Проект поддерживает **Node.js 24** (указан в `.nvmrc` и `package.json`).

---

## Быстрые настройки Timeweb (после последних изменений)

| Параметр | Значение |
|----------|----------|
| **Тип** | Docker → **Dockerfile** |
| **Репозиторий** | `prostodeniskdt-dot/portfolio` |
| **Ветка** | `main` |
| **Регион** | Москва / СПб / Амстердам |
| **Команда сборки** | *(не задавать — из Dockerfile)* |
| **Директория сборки** | *(не задавать — из Dockerfile)* |
| **Порт** | 8080 *(EXPOSE в Dockerfile)* |
| **Автодеплой** | Включить «Сборка по последнему коммиту» |

> Timeweb подтягивает код из GitHub. Перед деплоем выполните `git push`, чтобы все изменения попали в репозиторий.

## Два способа деплоя

### Вариант A: Frontend → Next.js + Node.js 24

Если вы выбираете **Next.js** и **Node.js 24** на экране «1. Тип»:

- Timeweb поддерживает только **статическую генерацию** (у нас `output: 'export'`).
- В настройках приложения укажите:
  - **Команда сборки**: `pnpm run build` (или `npm run build` при использовании npm)
  - **Директория сборки**: `out`
  - **Стартовая команда** (если требуется): `npx serve out -l 8080`
- При ошибке «Health check failed» переключитесь на **Вариант B**.

### Вариант B (рекомендуется): Docker → Dockerfile

Чтобы контейнер **запускался и проходил health check**, выберите тип **«Dockerfile»** на вкладке **Docker**. В репозитории есть готовый **Dockerfile** с **EXPOSE 8080** и **CMD** (`npx serve out -l 8080`).

- **Next.js** (тип Frontend): платформа может подставить шаблон **без CMD** — контейнер завершается, health check падает.
- **Dockerfile**: используется наш Dockerfile — контейнер стабильно запускает `serve` на порту 8080.

Для надёжного деплоя предпочтите **«Dockerfile»**.

---

## Что подготовлено в репозитории

- **next.config.mjs**: **`output: 'export'`**, без `distDir` — экспорт идёт в папку **`out`**.
- **Dockerfile**: одностадийная сборка (node:24-slim), установка зависимостей, `npm run build`, **EXPOSE 8080**, **CMD ["npx", "serve", "out", "-l", "8080"]**.
- **Dockerfile.nginx**: альтернатива с Nginx (меньший образ), см. в конце.
- **package.json**: **build** = `next build` (postbuild убран — используется только папка `out`).

**Серверные маршруты** (`/api/contact`, `/api/error`): при **статическом экспорте** они не работают — в проде нет Node-сервера. Окно «Контакты» на сайте использует только ссылки (Telegram, email), форму на API не отправляет, поэтому для сайта-визитки всё в порядке.

## Пошагово по панели Timeweb (экраны 1–6)

### 1. Регистрация и вход

1. Перейдите на [timeweb.cloud](https://timeweb.cloud/).
2. **«Войти»** или **«Создать аккаунт»**.
3. **«Сервисы»** → **«App Platform»** → **«Создать приложение»** / **«Добавить App»**.

---

### 2. Экран «1. Тип» (Frontend / Backend / Docker)

**Рекомендуемый путь (стабильный):**
- Перейдите на вкладку **«Docker»**.
- Тип приложения: **Dockerfile** — в корне репозитория уже есть файл **Dockerfile** (Node.js 24).

**Альтернативный путь (Next.js + Node.js 24):**
- Вкладка **«Frontend»** → выберите **Next.js** → **Node.js 24**.
- Если после деплоя health check не проходит, пересоздайте приложение с типом **Dockerfile**.

---

### 3. Экран «2. Репозиторий»

- **Аккаунт**: выберите ваш GitHub (например, `prostodeniskdt-dot`). Если аккаунта нет — **«Добавить аккаунт»** и привяжите GitHub.
- **Поиск**: введите **portfolio**. Выберите репозиторий **`prostodeniskdt-dot/portfolio`**.
- Если **portfolio** не отображается в списке: на GitHub откройте **Settings** → **Integrations** → **Applications** и выдайте Timeweb доступ к нужным репозиториям, либо сделайте репозиторий публичным. Подсказка в панели: «Настроить на Github».
- **Ветка**: оставьте **main** (или ту, с которой деплоите).
- **Сборка по последнему выполненному коммиту**: включите — деплой будет запускаться при каждом пуше в выбранную ветку.

---

### 4. Экран «3. Регион» и «4. Конфигурация»

- **Регион**: выберите ближайший (Москва, Санкт-Петербург, Амстердам и т.д.).
- **Конфигурация**: для статического сайта достаточно **2 ГБ NVMe** и оплаты по входящим запросам. «Примерный расчёт» — по желанию.

---

### 5. Экран «5. Настройка приложения»

При типе **Dockerfile** сборка и порт заданы в Dockerfile — поля **Команда сборки** и **Директория сборки** можно не менять (или оставить пустыми, если панель это позволяет). Платформа соберёт образ по Dockerfile и запустит `npx serve out -l 8080`.

Если по ошибке выбран тип **Next.js**, укажите:

| Поле | Значение |
|------|----------|
| **Команда сборки** | `npm run build` |
| **Зависимости** | пусто |
| **Директория сборки** | **`out`** (не `/dist/barboss/browser` — это от другого проекта). |

Переменные окружения для статического сайта не нужны.

---

### 6. Экран «6. Информация о приложении»

- **Имя**: например **portfolio** или **Сайт-визитка**.
- **Комментарий**: по желанию.
- **Проект**: выберите существующий или создайте новый (например, «Портфолио»).

Затем нажмите **«Запустить деплой»** (или аналог кнопки создания приложения).

## После деплоя

- В **Дашборде** приложения появятся **IP** и **технический домен** (например, `xxx.twc1.net`). Сайт будет доступен по HTTP/HTTPS по этому адресу.
- Свой домен привязывается в настройках приложения (см. ниже).

---

## Покупка домена и привязка к приложению

1. **Купить домен** можно в том же Timeweb: **«Домены»** → **«Зарегистрировать домен»** (или перенести домен от другого регистратора).
2. **Привязать домен к App**:
   - Откройте ваше приложение в App Platform → вкладка **«Домены»** / **«Настройки»**.
   - Добавьте домен (например, `yourname.ru` или `www.yourname.ru`).
   - В панели Timeweb будут показаны нужные **DNS-записи** (обычно A или CNAME на IP/адрес приложения). Пропишите их у регистратора домена (если домен куплен в Timeweb — часто подставляется автоматически).
3. Подробно: [Управление приложениями и привязка домена (Timeweb)](https://timeweb.cloud/docs/apps/upravlenie-apps-v-paneli#privyazka-domena).

## «Ошибка при сборке» или падение после «Build succeeded»

Часто это **не ошибка сборки**, а неудачный **health check**: контейнер собрался, но не слушает порт (нет процесса). Решение:

1. Выберите тип приложения **«Dockerfile»** (не «Next.js»). В нашем Dockerfile заданы **EXPOSE 8080** и **CMD ["npx", "serve", "out", "-l", "8080"]** — контейнер запускает сервер и отвечает на порту 8080.
2. При статическом экспорте **не используется** `next start` — в проекте запуск идёт через **serve** (в Dockerfile по CMD, в package.json по скрипту **start**).

---

## Если деплой падает на шаге «Unpacking static»

- Убедитесь, что в **next.config.mjs** задано **`output: 'export'`** и **не задано** `distDir` (экспорт должен идти в папку **`out`**).
- В настройках приложения в поле **«Директория сборки»** укажите **`out`**.

После изменений пересоберите и заново запустите деплой.

---

## Альтернатива: образ с Nginx (Dockerfile.nginx)

Для меньшего размера образа можно собрать его по **Dockerfile.nginx** (многостадийная сборка: Node → Nginx, раздача статики на порту 8080). В панели Timeweb при создании приложения укажите путь к Dockerfile: **Dockerfile.nginx** (если платформа это поддерживает), либо переименуйте файлы локально и запушьте. Документация: [деплой из Dockerfile в Timeweb](https://timeweb.cloud/docs/apps/deploying-with-dockerfile).
